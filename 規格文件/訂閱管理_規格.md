# A6.3 訂閱管理

v1.15｜2026-11-16｜PostgreSQL｜時間採 `timestamptz`，顯示時區採 `Asia/Taipei`。

設計依據為 A6.3 訂閱管理標註圖及最新確認的自主訂閱規則。A 的登記進度與訂閱狀態分開判斷，畫面依會員狀態擇一顯示。頁面原型見 [subscriptions.html](../subscriptions.html)，既有資料結構見 [db.txt](db.txt)。招租通知流程見[招租通知規格](招租通知_規格.md)，驗收情境及待確認事項另見[驗收與待確認事項](訂閱管理_招租通知_驗收與待確認事項.md)。

## 一、功能範圍

登入會員由會員選單進入「訂閱管理」，只能查詢及操作自己的訂閱。頁首說明為「管理您關注的區位與社宅招租通知。」

| 類型 | 畫面區塊 | 建立與管理方式 | 筆數 |
|---|---|---|---|
| A | 居住需求登記 | 完成登記問卷後，由會員自行按「訂閱」並確認才建立訂閱。透過問卷編輯條件，可取消及重新訂閱。 | 每會員最多一筆，固定在第一區塊。 |
| B | 已訂閱條件 | 從找社宅訂閱當次查詢條件，每次新增一筆。可取消。 | 可多筆，統計有效訂閱筆數。 |
| C | 已訂閱社宅 | 從找社宅訂閱指定社宅。可取消。 | 可訂閱多間社宅，同會員對同一社宅最多一筆有效訂閱。 |

### 1.1 訂閱條件

| 條件 | A 居住需求登記 | B 搜尋條件 | C 指定社宅 |
|---|---|---|---|
| 縣市／生活圈／行政區 | 讀取問卷 | 保存條件快照 | — |
| 房型（多選） | 讀取問卷 | 保存條件快照 | — |
| 租金範圍 | 讀取問卷 | 保存條件快照 | — |
| 公設服務（多選） | 讀取問卷 | 保存條件快照 | — |
| 指定社宅 ID | — | — | 保存單一社宅 ID |

依圖中「先不放進訂閱」註記，本版訂閱條件暫不納入生活機能及社宅名稱關鍵字。B 建立、推薦及通知媒合均使用上表四類條件。找社宅的 `housing_status_codes` 亦沿用原規劃，排除於訂閱條件外。

## 二、畫面與操作

### 2.1 區塊、欄位與呈現

區塊依序排列。

| 順序 | 區塊 | 欄位順序 |
|---|---|---|
| 1 | 居住需求登記 | 訂閱地區、房型、預算範圍、公設服務、訂閱日期、媒合推薦、操作 |
| 2 | 已訂閱條件 | 訂閱地區、房型、預算範圍、公設服務、訂閱日期、媒合推薦、操作 |
| 3 | 已訂閱社宅 | 社宅名稱、所在地區、訂閱日期、媒合推薦、操作 |

| 呈現項目 | 規則 |
|---|---|
| A 筆數 | 固定顯示一列狀態。已完成登記者顯示目前登記條件，包含尚未訂閱及已取消者。未完成登記時顯示空狀態。 |
| B／C 筆數與排序 | 只列 `status = 'ACTIVE'` 的資料，各自顯示有效筆數，依 `subscribed_at DESC, id DESC` 排序。 |
| B／C 空狀態 | 有效筆數為 0 時顯示該區空狀態及「前往找社宅」連結。 |
| 地區 | 依縣市分行，同縣市的多個行政區以「、」分隔。 |
| 房型與公設 | 顯示選項名稱，多選以「、」分隔，未限制時顯示「不限」。 |
| 預算 | 以每月新臺幣呈現，例如「NT$ 5,000–12,000／月」。只設單一端點時顯示「NT$ 5,000 起／月」或「NT$ 12,000 以下／月」，兩端皆空為「不限」。 |
| 訂閱日期 | 取 `subscribed_at`，以臺灣時間顯示 YYYY/MM/DD。A 編輯或重新訂閱保留首次訂閱日期。 |
| 已登記但尚未訂閱 | 顯示最新已送出問卷的條件，訂閱日期顯示「—」，操作為鉛筆圖示及「訂閱」。 |
| 未完成登記 | 訂閱地區欄顯示「無訂閱／尚未登記」，其他資料及媒合推薦顯示「—」。 |
| 按鈕 | 媒合推薦為放大鏡，編輯為鉛筆，皆提供可讀名稱及滑鼠提示。三區塊的日期、媒合推薦及操作欄對齊。 |

### 2.2 A 居住需求登記的狀態與操作

畫面須同時查詢問卷與 A 類訂閱，按下列順序判斷。

1. 依登入會員的 `member_id` 查本人最新 `status = 'SUBMITTED'` 的 `housing_demand_survey`。只有 DRAFT 時顯示「尚未登記」。
2. 有已送出問卷時，以同一個 `member_id` 及 `subscription_type = 'A'` 查 `member_subscription`，查詢包含 ACTIVE 與 CANCELLED。
3. 查無 A 列時，直接讀問卷顯示「尚未訂閱」及登記條件。有 A 列時，依該列的 `status` 顯示「已訂閱」或「已取消訂閱」。

| 畫面狀態 | 資料判斷 | 媒合推薦 | 操作及導向 |
|---|---|---|---|
| 無訂閱／尚未登記 | 本人無 SUBMITTED 問卷，包含尚未填寫或只有 DRAFT 草稿 | 無按鈕 | 「前往登記」導向居住需求問卷 `questionnaire.html`，已有草稿時依問卷流程續填。 |
| 尚未訂閱 | 本人有 SUBMITTED 問卷，尚無 A 訂閱列 | 有放大鏡按鈕 | 鉛筆圖示編輯居住需求，旁列「訂閱」，按下後開啟訂閱確認視窗。 |
| 已取消訂閱 | A 的 `status = 'CANCELLED'` | 有放大鏡按鈕 | 「重新訂閱」開啟確認視窗。 |
| 已訂閱 | A 的 `status = 'ACTIVE'` | 有放大鏡按鈕 | 鉛筆圖示導向「會員專區 ＞ 編輯居住需求」，頁面為 `questionnaire.html`。旁列「取消訂閱」。 |

完成問卷只保存登記資料。會員首次確認訂閱後才建立 A 列。尚未訂閱者編輯並送出問卷後仍為「尚未訂閱」。已有 A 列者重新送出問卷時，更新同一筆 A 的條件來源並保留當時的訂閱狀態。

尚未訂閱時，畫面與媒合推薦直接讀本人最新 SUBMITTED 問卷。通知程序依已建立且為 ACTIVE 的訂閱處理。

A 取消後保留登記資料與媒合推薦。另有符合的 B／C 有效訂閱時，通知程序仍可依該筆有效訂閱寄送招租通知。

### 2.3 訂閱、取消及重新訂閱確認

視窗上方均標示「招租通知設定」。按下確認並完成資料更新後才變更列表。「保留訂閱」、「返回」、Esc 或關閉視窗均維持原狀態。

| 操作 | 標題 | 視窗內容 | 按鈕 | 確認後結果 |
|---|---|---|---|---|
| A 首次訂閱 | 訂閱招租通知？ | 訂閱後，您會收到符合目前居住需求登記條件的招租通知。 | 返回／確認訂閱 | 新增 A 列，狀態為「已訂閱」，顯示訂閱日期、鉛筆圖示及「取消訂閱」。 |
| A 取消 | 取消訂閱？ | 取消後，將停止收到符合您居住需求的招租通知，登記資料仍會保留。 | 保留訂閱／確認取消 | 同一列改為「已取消訂閱」，操作改為「重新訂閱」。 |
| A 重新訂閱 | 重新訂閱？ | 重新訂閱後，您會收到符合目前居住需求登記條件的招租通知。 | 返回／確認訂閱 | 同一列改為「已訂閱」，操作改為鉛筆圖示及「取消訂閱」。 |
| B 取消 | 確定取消這筆訂閱？ | 帶入所選列的地區、房型、預算、公設摘要，並顯示「取消後將不再收到這筆招租通知，不影響您的其他訂閱與申請。」 | 保留訂閱／確認取消訂閱 | 移除該列，更新已訂閱條件筆數。 |
| C 取消 | 確定取消這筆訂閱？ | 帶入所選社宅名稱及所在地區，並顯示與 B 相同的取消說明。 | 保留訂閱／確認取消訂閱 | 移除該列，更新已訂閱社宅筆數。 |

取消操作由會員確認即可完成。服務更新 `status`、`cancelled_at`、`updated_at`。操作成功顯示結果，失敗時維持原資料並顯示失敗訊息。

### 2.4 媒合推薦

| 類型 | 查詢依據 | 結果 |
|---|---|---|
| A | 本人最新 SUBMITTED 問卷的區位、房型、租金、公設。已有 A 列者由 survey_id 取得，尚無 A 列者直接查問卷。 | 導至找社宅，帶入條件並顯示結果。尚未訂閱及已取消訂閱均可查詢。 |
| B | 訂閱時保存的區位、房型、租金、公設快照 | 導至找社宅，帶入保存條件並顯示結果。 |
| C | 指定 `housing_id` 及該社宅名稱 | 導至找社宅，名稱搜尋欄帶入社宅名稱，以 ID 限定僅顯示該社宅，避免同名社宅混入結果。 |

媒合推薦為即時搜尋。招租通知由背景排程依有效訂閱及招租時程處理。

## 三、訂閱資料表 `member_subscription`

### 3.1 用途與資料來源

每列代表一位會員曾明確確認的一筆訂閱，以 `subscription_type` 區分 A／B／C。已建立列的 `status` 表示目前為訂閱中或已取消，取消時間供紀錄操作時間使用。

**A 類首次確認訂閱前，`member_subscription` 沒有該會員的 A 類紀錄。** 問卷完成資料保存在 `housing_demand_survey`。該會員的 B／C 訂閱各自獨立，表內仍可能有 B／C 紀錄。

| 類型 | 條件來源 | 新增與更新方式 |
|---|---|---|
| A | `survey_id` 關聯本人最新 SUBMITTED 問卷 | 會員首次確認訂閱時建立。已存在 A 列時，後續送出問卷、取消與重新訂閱更新原列，每會員最多一列。 |
| B | 本表的區位、房型、租金、公設欄位 | 每次從找社宅訂閱條件時新增一列，保存當時條件。取消保留歷史，之後再次訂閱新增列。 |
| C | `housing_id` 指定單一社宅 | 同會員同社宅只保留一列有效訂閱。取消保留歷史，之後再次訂閱新增列。 |

B 條件沿用 `housing_search_log` 對應的代碼格式，由服務擷取本版四類條件並獨立保存。搜尋日誌清理或後續重新搜尋不影響已建立訂閱。C 的社宅名稱與地區從既有社宅、縣市、行政區主檔取得。

### 3.2 完整欄位

「必填＝是」設為 `NOT NULL`。「僅 A／B／C 必填」以 `CHECK` 依類型驗證。預設值「無」表示未設資料庫預設值，由服務寫入，選填欄位未填時存 `NULL`。

| 欄位 | PostgreSQL 型態 | 必填 | 預設值 | 關聯 | 用途／規則 |
|---|---|---|---|---|---|
| id | uuid | 是 | `gen_random_uuid()` | PK | 訂閱識別碼。A 編輯、取消及重新訂閱沿用同一 ID。 |
| member_id | uuid | 是 | 無 | FK → `member_profile.id` | 訂閱所屬會員，由登入身分取得。 |
| subscription_type | char(1) | 是 | 無 | — | 限 `A` 居住需求登記、`B` 搜尋條件、`C` 指定社宅。 |
| survey_id | uuid | 僅 A 必填 | 無 | FK → `housing_demand_survey.id` | 本人最新 SUBMITTED 問卷。A 取消後保留關聯。B／C 為 NULL。 |
| housing_id | uuid | 僅 C 必填 | 無 | FK → `housing.id` | 指定社宅，建立訂閱時須啟用。A／B 為 NULL。 |
| county_code | varchar(5) | 否 | 無 | FK → `county.county_code` | B 專用，縣市範圍，與 living_area_id 最多填一項。 |
| living_area_id | uuid | 否 | 無 | FK → `living_area.id` | B 專用，生活圈範圍，與 county_code 可皆為 NULL。 |
| district_codes | text[] | 僅 B 必填 | 無 | 元素對應 `district.district_code`，由服務驗證 | 行政區可複選、可跨縣市。B 未選時寫入空陣列 `'{}'`，A／C 為 NULL。 |
| room_type_codes | text[] | 僅 B 必填 | 無 | 元素對應 `housing_class.item_code`，限 ROOM_TYPE 群組 | 房型可複選。B 未選時寫入 `'{}'`，A／C 為 NULL。 |
| facility_codes | text[] | 僅 B 必填 | 無 | 元素對應 `housing_class.item_code`，限 FACILITY_ITEM 群組 | 公設可複選。B 未選時寫入 `'{}'`，A／C 為 NULL。 |
| rent_min | integer | 否 | 無 | — | B 專用，月租下限，單位為元，有值須 ≥ 0，NULL 表示無下限。 |
| rent_max | integer | 否 | 無 | — | B 專用，月租上限，單位為元，有值須 ≥ 0，NULL 表示無上限。兩端有值時須滿足 rent_min ≤ rent_max。 |
| status | varchar(20) | 是 | `'ACTIVE'` | — | `ACTIVE` 訂閱中、`CANCELLED` 已取消。預設值僅在會員確認訂閱後新增資料列時套用。畫面、統計、有效訂閱唯一性及通知排程均依此欄位判斷。 |
| subscribed_at | timestamptz | 是 | `now()` | — | 實際確認訂閱的時間，供列表顯示與排序。A 更新問卷或重新訂閱時保留首次訂閱日期。 |
| criteria_effective_at | timestamptz | 是 | 無 | — | 通知媒合生效時間。A 首次確認訂閱時與 subscribed_at 相同，已有 A 列再次送出問卷時取 submitted_at，重新訂閱時取恢復當下時間。B／C 新建時與 subscribed_at 相同。 |
| created_at | timestamptz | 是 | `now()` | — | 資料列建立時間，建立後保留。 |
| updated_at | timestamptz | 是 | `now()` | — | 更新問卷關聯、取消或重新訂閱發生實際異動時，由服務更新。 |
| cancelled_at | timestamptz | 否 | 無 | — | 紀錄當次取消時間。ACTIVE 時為 NULL，CANCELLED 時必填，A 重新訂閱時清空。重複取消保留原時間。 |

共 18 個欄位。A／C 的 B 專用欄位皆為 NULL，A 的四類條件直接讀問卷。三個多選陣列由服務驗證代碼及所屬群組。

資料庫預設值只在新增資料列時生效。完成問卷僅寫入問卷資料，因此此時沒有 A 列可套用 `status = 'ACTIVE'`、`subscribed_at` 或 `created_at` 等預設值。畫面顯示的「尚未訂閱」由「已有已送出問卷且查無 A 列」判斷。

### 3.3 訂閱狀態與異動

| A 類情境 | 問卷資料 | A 類訂閱紀錄 | status／cancelled_at | 寫入規則 |
|---|---|---|---|---|
| 尚未完成登記 | 無 SUBMITTED，可能有 DRAFT | 無 | 無資料列，欄位不適用 | 依問卷流程保存草稿。 |
| 已完成問卷，首次訂閱前 | 有 SUBMITTED | 無 | 無資料列，欄位不適用 | 只保存問卷。畫面有條件與媒合推薦，訂閱日期為「—」。 |
| 按「訂閱」後返回或關閉確認視窗 | 有 SUBMITTED | 無 | 無資料列，欄位不適用 | 維持尚未訂閱。 |
| 首次按「確認訂閱」成功 | 有 SUBMITTED | 新增一筆 | ACTIVE／NULL | 以本人最新已送出問卷設定 survey_id，訂閱、建立及生效時間取確認當下。 |
| 確認取消訂閱 | 有 SUBMITTED | 保留原列 | CANCELLED／當下時間 | 更新 status、cancelled_at、updated_at。 |
| 確認重新訂閱 | 有 SUBMITTED | 更新原列 | ACTIVE／NULL | 清空取消時間，依最新已送出問卷確認 survey_id，更新生效時間與 updated_at，保留首次訂閱日期。 |
| 首次訂閱前再次編輯並送出問卷 | 新增 SUBMITTED 版本 | 仍無 | 無資料列，欄位不適用 | 只保存新版問卷，維持尚未訂閱。 |
| 已有訂閱紀錄後編輯並送出問卷 | 新增 SUBMITTED 版本 | 更新原列 | status、cancelled_at 保留原值 | 更新 survey_id、criteria_effective_at、updated_at，保留 id、subscribed_at、created_at。 |

A 的「尚未登記」、「尚未訂閱」由問卷與 A 列是否存在共同判斷。訂閱表內每一列的 status 都必填，取值限 ACTIVE／CANCELLED。

| B／C 類情境 | 寫入規則 |
|---|---|
| 確認建立訂閱 | 新增 ACTIVE 列，cancelled_at 為 NULL，寫入訂閱、建立及條件生效時間。 |
| 確認取消 | 原列改為 CANCELLED，寫入取消時間及 updated_at，保留原條件及訂閱日期。 |
| 取消後再次從找社宅訂閱 | 原列保留 CANCELLED，新建 ACTIVE 列，使用新的 ID 及訂閱時間。 |

### 3.4 資料規則與驗證

| 層級／項目 | 規則 |
|---|---|
| CHECK 類型 | subscription_type 限 A／B／C。 |
| CHECK 類型與欄位 | A 必填 survey_id 且 housing_id 為 NULL。B 的 survey_id、housing_id 為 NULL，三個多選陣列皆必填。C 必填 housing_id 且 survey_id 為 NULL。所有 B 專用欄位在 A／C 均為 NULL。 |
| CHECK 區位與預算 | county_code、living_area_id 最多一項有值。租金端點有值時非負，兩端有值時 rent_min ≤ rent_max。 |
| CHECK 狀態與取消時間 | status 僅允許 ACTIVE／CANCELLED。ACTIVE 時 cancelled_at 為 NULL，CANCELLED 時 cancelled_at 必須有值且 ≥ subscribed_at。 |
| 會員權限 | 以登入會員身分驗證訂閱歸屬，所有查詢及異動限定本人 member_id。 |
| A 建立時機 | 只有會員首次明確確認訂閱才新增 A 列。送出問卷、開啟訂閱管理、查看媒合推薦及返回確認視窗均不新增訂閱列。 |
| A 首次訂閱 | 驗證本人已有最新 SUBMITTED 問卷，會員明確確認後建立 A，設定 ACTIVE，訂閱與生效時間取確認當下。重複確認時回傳既有列，保留原訂閱及生效時間。 |
| A 問卷版本 | 正式送出問卷時，若已有 A 列則在同一交易更新其問卷關聯；無 A 列時只保存問卷。驗證關聯問卷屬於本人且為最新已送出版本，草稿不影響訂閱。 |
| A 編輯 | 更新條件保留原狀態，已取消者編輯送出後仍維持 CANCELLED。 |
| A 重新訂閱 | 只恢復本人已取消的 A 原列。重複確認已為 ACTIVE 的訂閱時回傳目前狀態，保留既有生效時間。 |
| 取消 | 以 member_id、id 及 status = 'ACTIVE' 更新為 CANCELLED。重複確認已取消列時維持原取消時間。 |
| B 陣列 | 驗證每個代碼存在、群組正確，去除重複值，元素不得為 NULL 或空字串。空陣列代表該項未限制。 |
| B 區位 | 先套用縣市或生活圈，再套行政區。兩範圍皆空且有行政區時，依指定行政區限定；全部未指定時為不限地區。驗證行政區與選定範圍一致。 |
| A 區位 | 沿用問卷將各縣市「全區」展開為行政區代碼的規則。 |
| C 社宅 | 建立時驗證社宅啟用。社宅停用時保留訂閱列，推薦依找社宅的可見性規則呈現。 |
| 並行更新 | A 送出問卷、首次訂閱、取消與重新訂閱在交易內鎖定同一會員，取得鎖後重查問卷與訂閱狀態。已有 CANCELLED 列時依重新訂閱確認流程恢復原列。C 以有效訂閱部分唯一索引處理同時訂閱衝突，回傳既有有效列。 |
| 資料保留 | 取消保留原列。外鍵刪除採 NO ACTION。A 更新原列保存目前訂閱狀態與當次取消時間。 |
| 通知銜接 | 以實際存在且 status = 'ACTIVE' 的訂閱列為媒合來源。只有問卷、查無 A 列的會員不會依問卷產生通知配對；仍可依本人符合的有效 B／C 訂閱處理。A／B 比對區位、房型、租金、公設，C 比對指定社宅。寄送前再次確認狀態，生效時間比對沿用招租通知規格的暫定規則。 |

### 3.5 狀態檢核範例

下列 PostgreSQL 約束在資料表建立時設定。

```sql
CHECK (
    status IS NOT NULL
    AND (
        (status = 'ACTIVE' AND cancelled_at IS NULL)
        OR
        (status = 'CANCELLED'
            AND cancelled_at IS NOT NULL
            AND cancelled_at >= subscribed_at)
    )
)
```

## 四、索引

| 索引 | 用途 |
|---|---|
| PRIMARY KEY (id) | 訂閱唯一識別。 |
| UNIQUE (member_id) WHERE subscription_type = 'A' | 每會員最多一筆 A，涵蓋有效及已取消列。 |
| UNIQUE (member_id, housing_id) WHERE subscription_type = 'C' AND status = 'ACTIVE' | 同會員同社宅最多一筆有效 C。 |
| INDEX (member_id, subscription_type) | 查詢會員 A 狀態及各類訂閱。 |
| INDEX (member_id, subscribed_at DESC, id DESC) WHERE status = 'ACTIVE' | 有效訂閱列表與排序。 |
| INDEX (subscription_type, criteria_effective_at) WHERE status = 'ACTIVE' | 支援招租通知排程篩選。 |
