# 帳號管理功能規格

**功能入口**　系統營運管理 → 帳號權限管理 → 帳號管理  
**依據**　[帳號管理畫面](../backend/account-management.html)、[互動與示範資料](../backend/assets/js/account-management.js)、[頁面樣式](../backend/assets/css/account-management.css)、[後臺分頁元件](../後臺模板/components/pagination.html)

管理人員分別維護前臺民眾與後臺機關帳號。兩個頁籤都只列曾成功登入的帳號。機關帳號使用機關憑證登入後臺。現行畫面為記憶體示範，以下註明與正式功能有差異之處。

## 1. 查詢條件

預設開啟「民眾帳號」。切換至「機關帳號」後，查詢區增加機關名稱、機關角色。頁籤支援滑鼠、左右方向鍵及 Home／End。可展開或收合查詢區。空間足夠時機關查詢條件排列於同一行，關鍵字欄保留較寬空間。

| 條件 | 適用頁籤 | 比對規則 |
|---|---|---|
| 關鍵字 | 兩者 | 去除首尾空白後，比對真實姓名、身分證／居留證號、聯絡手機或電子信箱。任一欄包含關鍵字即符合，英文字母不分大小寫。 |
| 機關名稱 | 機關 | 預設「全部機關」。選取機關時比對完整值。第一個具名選項為「內政部國土管理署」。 |
| 機關角色 | 機關 | 預設「全部機關角色」。全部機關時列出五種角色，選定機關後依第 6 節連動。切換機關時保留仍適用的角色，否則回到「全部機關角色」。 |
| 狀態 | 兩者 | 全部狀態、啟用、停用。 |

按「查詢」時，各條件取交集。切換頁籤時保留欄位值，重新查詢目前頁籤，民眾查詢忽略機關專用條件。「重設」清空全部查詢條件。查詢、切換頁籤及重設均回到第 1 頁。

正式串接時，民眾的證號依完整證號比對；機關頁以可取得的帳號識別或顯示名稱查詢。現行示範的兩頁皆使用明文證號做包含比對。

## 2. 查詢結果

每列代表一個符合條件的帳號，依序提供「檢視」、「編輯」操作。列表上方顯示目前筆數範圍、總筆數與頁次。零筆時顯示「共 0 筆帳號」及「查無符合條件的帳號。」。

### 2.1 排序

先篩選，再排序全部符合條件的帳號，最後取出當頁。兩個頁籤各自記住當次開頁的排序，預設最後登入時間降冪。桌面點選資料欄名，行動版選擇欄位並切換升降冪。「操作」欄不可排序，電子信箱欄依地址排序。

選取新欄位時，最後登入時間預設降冪，其餘欄位預設升冪。再次點選同一欄即反轉，並回到第 1 頁。文字採繁體中文自然排序，數字片段按數值比較，狀態升冪時停用在前。同值時一律依帳號內部識別碼升冪，確保跨頁順序穩定。表頭以箭頭及 aria-sort 表示目前排序。

### 2.2 分頁

- 列表下方固定顯示每頁筆數、導覽頁碼與跳頁控制。每頁可選 10、20、50、100 筆，預設 20 筆。變更時，原頁的第一筆資料仍落在新顯示的頁面。
- 提供第一頁、上一頁、頁碼、下一頁、最後一頁。使用模板的橘色實心圓標示目前頁。保留首末頁碼，中間顯示最多七個連續頁碼；只隔一頁時直接補出該頁，更大間隔顯示不可點選的省略號。
- 例如共 100 頁，第 1 頁呈現「|<　<<　1　2　3　4　5　6　7　…　100　>>　>|」；第 50 頁呈現「|<　<<　1　…　47　48　49　50　51　52　53　…　100　>>　>|」。
- 跳頁接受 1 至總頁數的整數，按 Enter 或「前往」切換。從分頁導覽或跳頁切換後，焦點及捲動位置回到結果摘要。首頁停用往前控制，末頁停用往後控制。只有一頁或零筆時仍保留第 1 頁，停用跳頁及前後導覽。

## 3. 資料欄位

| 順序 | 欄位 | 顯示規則 |
|---|---|---|
| 1–3 | 真實姓名、身分證／居留證號、聯絡手機 | 現行示範兩頁皆顯示；正式機關帳號以顯示名稱與帳號識別取代個人姓名與證號。手機保留前導零並單行顯示。 |
| 4 | 電子信箱 | 驗證圖示與信箱放在同一欄，地址單行顯示。勾號代表已驗證，驚嘆號代表未驗證。 |
| 5–6（機關限定） | 機關名稱、機關角色 | 民眾列表略過這兩欄。機關角色以單行標籤顯示。 |
| 接續 | 最後登入時間 | 必有值，格式為 YYYY/MM/DD HH:mm:ss，精確到秒。 |
| 接續 | 狀態 | 窄欄置中，勾號代表啟用，禁止符號代表停用。狀態與驗證圖示均提供文字提示及無障礙名稱。 |
| 末欄 | 操作 | 「檢視」與「編輯」並排，開啟該筆帳號的彈窗。 |

列表文字至少 16px，窄螢幕依欄名與值呈現，電子信箱及機關角色維持單行。正式版民眾證號欄提供授權檢視，停用證號排序。

## 4. 檢視

點選該列「檢視」開啟「檢視帳號資料」。以深色唯讀文字顯示識別資料、聯絡手機、電子信箱、帳號類型與狀態；機關帳號另顯示所屬機關及機關角色。信箱下方以綠色勾號搭配驗證時間，或以紅色驚嘆號搭配「信箱尚未驗證」。下方顯示首次驗證方式及時間，底部只提供「關閉」。最後登入時間顯示於列表。

民眾的首次驗證方式可為自然人憑證、行動自然人憑證或健保卡號與身分證字號比對。正式機關帳號顯示「機關憑證」。

## 5. 編輯

點選「編輯」開啟該帳號資料。底部提供圓角「關閉」、「儲存」按鈕。

| 彈窗欄位 | 編輯規則 |
|---|---|
| 真實姓名 | 必填，最多 100 字元。 |
| 身分證字號／居留證號 | 唯讀，資料長度上限 20 字元。 |
| 聯絡手機 | 必填，最多 20 字元，保留前導零。 |
| 電子信箱 | 必填，最多 254 字元，通過電子郵件格式檢查。 |
| 角色 | 正式版依登入來源固定為民眾或機關。現行示範仍提供類型切換。 |
| 機關名稱、機關角色 | 機關帳號必填，僅授權管理者可變更。民眾帳號不顯示。 |
| 狀態 | 必選啟用或停用。 |
| 首次身分驗證方式、首次身分驗證時間 | 唯讀。依帳號類型顯示第 4 節所列方式。 |

信箱下方同步顯示圖示及訊息。已驗證以綠色顯示「驗證時間：YYYY/MM/DD HH:mm:ss」，未驗證以紅色顯示「信箱尚未驗證」。編輯成不同地址時即時預覽未驗證狀態，儲存前改回原址會恢復原提示。

1. 關閉視窗會放棄未儲存的修改。儲存時檢查必填、長度、信箱格式及機關選項。姓名、手機與信箱去除首尾空白。
2. 信箱變更時清除原驗證時間及已驗證狀態。正式版只更新可編輯欄位，民眾及機關分別啟停用。
3. 儲存成功後關閉彈窗，顯示「已更新『姓名』的示範資料」提示，重新套用目前的查詢及排序。盡量保留當前頁次，超過新的末頁則回到末頁。帳號不再符合查詢時，自目前結果移除。
4. 狀態及機關角色可在本頁維護。現行頁面未實作後端授權、建立或刪除帳號、寄送驗證信、密碼重設。角色名稱不等同已實作的權限清單。

## 6. 機關與角色權限

機關名稱決定帳號所屬單位，機關角色決定可執行的功能。選取機關或成功使用機關憑證登入，均不會自動取得該機關的所有權限。

### 6.1 機關對應角色

下表為查詢條件的機關與角色對應。選機關後立即更新角色選單，按「查詢」套用條件。重設後恢復全部機關與全部五種角色。

| 所屬機關 | 可查詢角色 | 資料範圍 |
|---|---|---|
| 內政部國土管理署 | 系統管理員、國土署管理員、國土署人員 | 署內與跨機關的可見範圍，依核定業務授權。 |
| 國家住宅及都市更新中心 | 社宅機關人員、社宅機關查調人員 | 所屬機關。 |
| 新北市政府、臺北市政府、桃園市政府、臺中市政府、臺南市政府、高雄市政府 | 社宅機關人員、社宅機關查調人員 | 各自所屬機關。 |

系統管理員為平臺層級的角色，須另外授予。查詢時歸入內政部國土管理署，可授予此角色的人員尚待核定。

### 6.2 角色可以做什麼

| 機關角色 | 帳號查詢、檢視 | 編輯、啟停用及角色指派 | 業務與案件查調 |
|---|---|---|---|
| 系統管理員 | 建議可查詢兩類帳號 | 建議可維護兩類帳號；授予系統管理員的流程另行核定 | 案件查調須另有業務授權。 |
| 國土署管理員 | 建議可查詢授權範圍內的機關帳號 | 建議可維護獲授權的機關帳號；可指派哪些角色、能否維護民眾帳號待核定 | 跨機關案件範圍及查調權待核定。 |
| 國土署人員 | 是否需使用帳號查詢待核定 | 建議預設不開放帳號維護或授權 | 依署內業務分工授權，案件檢視範圍待核定。 |
| 社宅機關查調人員 | 帳號管理查詢權未定義 | 帳號維護及角色指派權未定義 | 已定義：一般機關功能，並可檢視**所屬機關案件**的查調資料。 |
| 社宅機關人員 | 帳號管理查詢權未定義 | 帳號維護及角色指派權未定義 | 已定義：一般機關功能，不具查調資料檢視權。 |

後兩種角色分別對應原「查調授權人員」與「一般機關人員」，依據[原角色定義](../account-management-spec.md)。其餘標為「建議」或「待核定」者，尚非現行授權。正式服務應分別檢查查詢、檢視、編輯、啟停用、角色指派及目標資料範圍，未核定的權限預設不開放。

## 7. 功能驗收

| 情境 | 操作與預期結果 |
|---|---|
| 初次開啟 | 示範民眾 202 筆，預設每頁 20 筆、共 11 頁。切至機關有 398 筆、共 20 頁。兩者預設最近登入在前，每筆均有最後登入時間。 |
| 查詢條件 | 以部分信箱可找到帳號，再加狀態後僅保留交集。民眾頁籤不受機關篩選值影響。查無資料可重設回目前頁籤第 1 頁。 |
| 各頁籤排序 | 在機關頁點「機關名稱」兩次可切換方向。切到民眾頁維持該頁籤自己的排序；再切回機關保留剛才方向。 |
| 分頁邊界 | 第一頁不可再往前，直接跳至末頁後不可再往後。0、非整數及超過總頁數的輸入不換頁。共 100 頁時可直接點選首尾頁碼。 |
| 唯讀與關閉 | 檢視顯示黑字資料及驗證資訊，沒有儲存按鈕。編輯後直接關閉，再開啟仍是原值。 |
| 信箱變更 | 以已驗證帳號換信箱，提示立即變紅；儲存後列表圖示同步更新，再開啟不顯示舊驗證時間。 |
| 類型與狀態 | 正式版不提供民眾與機關互轉。帳號改為停用後，在「啟用」查詢結果中移除。 |
| 機關查調範圍 | 社宅機關查調人員僅可檢視所屬機關案件的查調資料，社宅機關人員不可檢視。 |

## 附錄 A　PostgreSQL 資料表設計

**正式版建議採兩張帳號主檔。** 民眾登入前臺，沿用 member_profile；機關帳號專供後臺，以機關憑證驗證，另設 agency_account。兩者各自管理識別、啟停用、登入紀錄及最後成功登入時間。管理頁共用查詢、排序、分頁與顯示格式，各頁籤分別讀取其資料來源。以下「既有」指提供的 DBML 已定義，「建議新增」尚未實作。

### A.1 民眾資料沿用範圍

| 資料 | 既有來源及規則 |
|---|---|
| 會員識別與聯絡方式 | member_profile.id（UUID）、member_name、mobile_phone、email。登記完成建立會員，停用保留資料。 |
| 證號 | id_no_hash、id_no_encrypted、id_no_key_version。授權顯示時由服務解密，完整證號以 HMAC 查找。正式版建議證號只支援完整比對，停用證號排序；其他關鍵字仍支援包含比對。居留證格式支援須與身分服務核對。 |
| 信箱驗證 | email_verified_at、產生欄位 is_email_verified。信箱變更時清空驗證時間。member_email_verification 為登記前驗證碼紀錄。 |
| 首次身分驗證及狀態 | first_auth_type 對應 AUTH_TYPE 字典，first_auth_at 記錄時間，is_enabled 決定啟停用。 |
| 登入 | 已有 member_login_log，建議在 member_profile 新增 last_login_at 作列表摘要，詳見 5.3。 |

### A.2 機關帳號與憑證識別（建議新增）

帳號、機關與憑證分別有自己的識別碼。同機關可有多個後臺帳號；機關名稱沿用 housing_class 的 AGENCY 群組。憑證驗證成功後，服務須能將此次登入唯一對應到已授權的帳號，再依該帳號的啟用狀態及角色決定是否允許登入。

| 表 | 欄位與約束 | 用途 |
|---|---|---|
| agency_account | id uuid PK、agency_id uuid NOT NULL、agency_role_id uuid NOT NULL | agency_id 外鍵指向 housing_class.id，服務限定 AGENCY 群組。角色引用既有授權主檔，或採下列 AGENCY_ROLE 字典。 |
| agency_account | display_name varchar(100)、mobile_phone varchar(20)、email varchar(254)、email_verified_at timestamptz 可空 | 顯示名稱與聯絡資料由帳號建置流程提供。驗證時間對應目前信箱，變更信箱與清空時間須在同一交易完成。 |
| agency_account | is_enabled boolean NOT NULL、first_auth_at timestamptz、last_login_at timestamptz、created_at、updated_at（均為 timestamptz） | 驗證方式顯示「機關憑證」。帳號若先建檔後登入，登入相關時間初始可空，管理列表僅列曾成功登入的帳號。 |
| agency_account_credential（如由本系統管理綁定） | id uuid PK、account_id uuid FK、issuer、credential_identifier、bound_at timestamptz、revoked_at timestamptz 可空 | 以驗證服務可提供的簽發者及憑證識別值管理換發、撤銷。換發沿用同一帳號 UUID 及歷程。若上游已提供穩定、可唯一對應帳號的識別，可直接保存其對應關係。 |

**憑證識別粒度是定案前要確認的一點。** 若一張憑證由多人共用且只能辨識機關，憑證本身無法區分同機關的兩名操作人。若要授予不同人不同角色或追溯個人操作，登入流程須再驗證可唯一識別人員的身分。若業務採共用帳號，登入紀錄只能歸屬該機關帳號。憑證序號不宜作為永久帳號主鍵，私人金鑰與 PIN 不存入帳號或日誌。

| 順序 | 建議 AGENCY_ROLE.item_code | item_name | 舊名稱對應 |
|---:|---|---|---|
| 1 | SYSTEM_ADMIN | 系統管理員 | — |
| 2 | NLMA_MANAGER | 國土署管理員 | — |
| 3 | NLMA_STAFF | 國土署人員 | — |
| 4 | HOUSING_INQUIRY | 社宅機關查調人員 | 查調授權人員 |
| 5 | HOUSING_STAFF | 社宅機關人員 | 一般機關人員 |

機關選單先核對 AGENCY 是否涵蓋內政部國土管理署、國家住宅及都市更新中心、新北市政府、臺北市政府、桃園市政府、臺中市政府、臺南市政府及高雄市政府。DBML 未附完整字典資料。查詢預設「全部機關」，本頁第一個具名選項為內政部國土管理署；其餘依字典排序。本頁置頂可用查詢排序實作，避免改動其他模組的選單。

### A.3 兩端登入紀錄與最後登入時間

| 登入入口 | 逐次事件 | 列表摘要 |
|---|---|---|
| 民眾前臺 | 沿用 member_login_log，以 member_id 對應 member_profile.id | 建議新增 member_profile.last_login_at |
| 機關後臺 | 新增 agency_login_log：id bigint PK、agency_account_id uuid、occurred_at timestamptz、event_type、result、source_ip。無法辨識帳號的失敗嘗試允許帳號鍵為空。 | 建議新增 agency_account.last_login_at |

兩端均記錄登入成功、登入失敗及登出事件，只增不改。同一交易寫入成功登入事件並更新對應主檔的 last_login_at，並行登入取較新時間。登入失敗、停用遭拒、登出均保留事件，不更新該摘要。api_session 與 api_auth_log 專供系統介接驗證，不作為人員登入來源。

既有民眾摘要以 member_login_log 中 event_type = 'LOGIN'、result = 'SUCCESS' 且 member_id 有值的 MAX(occurred_at) 依會員回填。兩個頁籤均查 last_login_at IS NOT NULL，因此每筆列表紀錄都有時間；停用後仍保留上次成功時間。缺少可靠歷史事件時不以建立時間或更新時間補值。各主檔可建 (last_login_at DESC, id ASC) 的非空部分索引供預設分頁，各日誌依帳號與發生時間查詢。畫面統一以 Asia/Taipei 顯示至秒。

### A.4 正式版畫面與驗收差異

正式串接時依下列案例驗收。

1. 帳號類型依來源固定，移除跨頁籤轉換。即使同一人同時有民眾與機關帳號，停用一方亦不影響另一方。
2. 機關彈窗顯示「機關憑證」及首次驗證時間。機關列表與關鍵字使用正式可取得的帳號識別或顯示名稱，不要求複製民眾證號。角色授予由後臺授權服務檢查，僅持有效機關憑證不會自動取得管理權限。
3. 驗收時分別以兩端帳號成功登入，再測試失敗及登出。各自列表的最後登入時間應維持在該端最近一次成功登入；兩端事件可分別查得。機關憑證換發後，既有帳號的角色、啟停用狀態與歷程應延續。
4. 兩個頁籤各自以相同條件計數與取頁；排序同值最終以各自主檔 id 升冪。另測試錯誤群組與未授權角色的指派被拒絕、變更信箱後驗證狀態重設。
