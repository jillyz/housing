# A6.3 訂閱管理與招租通知－驗收與待確認事項

規格見[訂閱管理規格](訂閱管理_規格.md)及[招租通知規格](招租通知_規格.md)。

## 一、建議驗收情境

| 編號 | 測試情境 | 預期結果 |
|---|---|---|
| T01 | 已訂閱 A 的會員再次正式送出問卷 | A 仍只有一筆，更新 survey_id 與 criteria_effective_at，保留原訂閱狀態。 |
| T02 | B 類訂閱臺中市西屯區、二房型、租金上限 18,000 及公設服務 | 單筆訂閱保存區位、房型、租金、公設四類條件。 |
| T03 | B 類只選臺中市、不選其他條件 | 可建立有效訂閱；其他條件視為不限 |
| T04 | 同會員對同一社宅連按訂閱 | 只允許一筆有效 C 類訂閱 |
| T05 | C 類取消後從找社宅再次訂閱 | 舊筆保留 CANCELLED 及 cancelled_at，新列為 ACTIVE。 |
| T06 | 招租時程尚未介接 | 訂閱仍可建立，無招租依據不寄信 |
| T07 | 同招租案同時符合 A、B、C | 產生一筆通知，快照列出所有符合的訂閱與社宅 |
| T08 | 聯合招租兩間社宅均符合 B 類 | 一筆通知，快照記錄兩間不同 `housing_id` |
| T09 | 同招租案 API 重送且 schedule ID 不變 | 不重複寄信 |
| T10 | API 晚到、招租已開始且仍在招租期間 | 次日排程可補做尚未處理通知（須符合訂閱生效日規則） |
| T11 | Email 發送失敗後重試 | 同一通知主檔更新嘗試次數與狀態 |
| T12 | 會員停用、Email 未驗證，或寄送前所有符合的 A／B／C 訂閱皆為 CANCELLED | 寄送前阻止發送；首次登記寄送前仍有其他 ACTIVE 配對時，僅保留有效配對通知。 |
| T13 | 找社宅同時設定四類訂閱條件、生活機能及名稱關鍵字後建立 B | 本版訂閱僅保存區位、房型、租金、公設。推薦及通知均依保存的四類條件。 |
| T14 | A 類舊問卷在招租開始後才被修改成符合條件 | 不以新條件追溯發送較早已開始的招租（依本版建議規則） |
| T15 | 會員有一筆 A、兩筆 B、兩筆有效 C | 依序顯示居住需求登記、已訂閱條件、已訂閱社宅。A 顯示一列，B、C 各為 2 筆。跨縣市行政區在同列分組呈現。 |
| T16 | A 點鉛筆編輯並正式送出新版問卷 | 導至會員專區編輯居住需求，更新原筆 survey_id 與條件生效時間，保留首次訂閱日期及原 status。 |
| T17 | A、B、C 各點媒合推薦 | 找社宅立即顯示結果；A、B 還原各自完整條件，C 同名時只顯示指定 ID。 |
| T18 | 分別開啟 B、C 取消視窗，再選保留或確認 | 核對摘要與所點列相符；保留不變，確認後僅該區少一筆，其他訂閱及申請保留。 |
| T19 | 會員已有有效 A／B／C 訂閱，符合條件的招租時程開始 | 依排程產生通知，不需另外啟用通知或檢查通知同意；member_profile 不新增通知欄位 |
| T20 | 已建單但尚未登記寄送時，會員新增符合的 B／C 訂閱，或更換已驗證 Email | 寄送前重算配對併入同一封通知；收件地址更新為目前已驗證 Email |
| T21 | 已登記寄送嘗試並進入 RETRY 後，會員更換 Email 或有訂閱取消 | 該筆 SKIPPED，不向舊地址寄送，也不縮減內容後重送 |
| T22 | 同一會員的 A、B 兩筆訂閱，只有 B 符合某招租時程 | 仍產生通知；各訂閱獨立判斷，不要求 A、B 同時符合 |
| T23 | A 尚未填寫或只有 DRAFT | 只顯示「無訂閱／尚未登記」一列，資料及推薦顯示「—」，操作為「前往登記」，無須建立空白訂閱列。 |
| T24 | A 取消視窗分別選保留及確認 | 保留維持原狀態；確認後原列為 CANCELLED、寫入取消時間，保留問卷與推薦按鈕，操作改為「重新訂閱」。 |
| T25 | A 重新訂閱視窗分別選返回及確認 | 返回維持 CANCELLED；確認後同一 ID 改為 ACTIVE、清空取消時間、更新生效時間，恢復鉛筆及取消按鈕。 |
| T26 | 寫入 ACTIVE 且有取消時間，或 CANCELLED 且無取消時間 | 資料庫拒絕不一致的狀態與時間組合。 |
| T27 | 首次完成登記，或從未訂閱的會員再次送出問卷 | 只保存問卷，無 A 訂閱列，畫面顯示條件、推薦按鈕及「訂閱」，訂閱日期為「—」。 |
| T28 | 已完成登記者首次訂閱，分別選返回及確認 | 返回維持未訂閱；確認後才建立 ACTIVE 的 A 列，訂閱日期與生效時間取確認當下。重複確認維持原列及原時間。 |
| T29 | 只有已完成問卷、尚未確認訂閱 A 的會員符合某招租案，且無其他符合的有效訂閱 | 通知程序無有效配對，不建立通知。媒合推薦仍可使用。 |

## 二、尚待業務／技術確認

1. **多選公設的比對**：採「任一符合（OR）」或「全部符合（AND）」？須與找社宅原有搜尋規則一致。
2. **B 類租金預設值**：現有搜尋畫面預設 0～40,000 元，訂閱時要儲存此範圍，還是將未調整預算視為不限？需一致。
3. **B 類社宅狀態**：本規劃排除 `housing_status_codes`，因其與招租通知目的高度重疊；若業主要求完全複製搜尋條件須再納入。
4. **訂閱時間與既有招租**：本版建議「只通知條件生效後開始的招租」，A 重新訂閱從恢復當下起算；若希望收到已進行中的招租，須調整排程規則。
5. **招租案唯一識別**：國住都及六都推送 `rental_schedule.schedule_code` 是否必填且穩定？若可空導致重複建立招租案，必須另訂通知去重方式。
6. **寄送頻率**：每日 08:00 為建議值；若招租期短或需高時效，可調整頻率但不需要修改資料表架構。
