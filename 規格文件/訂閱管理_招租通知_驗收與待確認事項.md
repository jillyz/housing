# A6.3 訂閱管理與招租通知－驗收與待確認事項

規格見[訂閱管理規格](訂閱管理_規格.md)及[招租通知規格](招租通知_規格.md)。

## 一、建議驗收情境

| 編號 | 測試情境 | 預期結果 |
|---|---|---|
| T01 | 同一會員完成 A 類問卷後再次正式提交 | A 類仍只有一筆；`survey_id` 與 `criteria_effective_at` 更新 |
| T02 | B 類訂閱「青年」、臺中市西屯區、二房型、租金上限 18,000 | 單筆訂閱完整保存所選條件，關鍵字不遺失 |
| T03 | B 類只選臺中市、不選其他條件 | 可建立有效訂閱；其他條件視為不限 |
| T04 | 同會員對同一社宅連按訂閱 | 只允許一筆有效 C 類訂閱 |
| T05 | C 類取消後重新訂閱 | 舊筆保留 cancelled_at，新建一筆有效訂閱 |
| T06 | 招租時程尚未介接 | 訂閱仍可建立，無招租依據不寄信 |
| T07 | 同招租案同時符合 A、B、C | 產生一筆通知，快照列出所有符合的訂閱與社宅 |
| T08 | 聯合招租兩間社宅均符合 B 類 | 一筆通知，快照記錄兩間不同 `housing_id` |
| T09 | 同招租案 API 重送且 schedule ID 不變 | 不重複寄信 |
| T10 | API 晚到、招租已開始且仍在招租期間 | 次日排程可補做尚未處理通知（須符合訂閱生效日規則） |
| T11 | Email 發送失敗後重試 | 同一通知主檔更新嘗試次數與狀態 |
| T12 | 會員停用、Email 未驗證，或寄送前所有符合的 B／C 訂閱皆已取消且無其他有效配對 | 寄送前阻止發送；仍有其他符合的有效訂閱時，僅保留有效配對通知 |
| T13 | B 類社宅名稱關鍵字包含 `%`、`_`、`[` | 作為一般文字查找，不誤當 SQL LIKE 萬用字元 |
| T14 | A 類舊問卷在招租開始後才被修改成符合條件 | 不以新條件追溯發送較早已開始的招租（依本版建議規則） |
| T15 | 會員有一筆 A、兩筆 B、兩筆有效 C | 分區顯示 3 筆及 2 筆；A 固定第一列。跨縣市行政區在同列分組呈現。 |
| T16 | A 點更新條件後分別選擇兩個按鈕 | 留在本頁不寫入；前往問卷導至編輯居住需求，重新送出後回查仍為原筆。 |
| T17 | A、B、C 各點媒合推薦 | 找社宅立即顯示結果；A、B 還原各自完整條件，C 同名時只顯示指定 ID。 |
| T18 | 分別開啟 B、C 取消視窗，再選保留或確認 | 核對摘要與所點列相符；保留不變，確認後僅該區少一筆，其他訂閱及申請保留。 |
| T19 | 會員已有有效 A／B／C 訂閱，符合條件的招租時程開始 | 依排程產生通知，不需另外啟用通知或檢查通知同意；member_profile 不新增通知欄位 |
| T20 | 已建單但尚未登記寄送時，會員新增符合的 B／C 訂閱，或更換已驗證 Email | 寄送前重算配對併入同一封通知；收件地址更新為目前已驗證 Email |
| T21 | 已登記寄送嘗試並進入 RETRY 後，會員更換 Email 或有訂閱取消 | 該筆 SKIPPED，不向舊地址寄送，也不縮減內容後重送 |
| T22 | 同一會員的 A、B 兩筆訂閱，只有 B 符合某招租時程 | 仍產生通知；各訂閱獨立判斷，不要求 A、B 同時符合 |

## 二、尚待業務／技術確認

1. **多選公設、生活機能的比對**：採「任一符合（OR）」或「全部符合（AND）」？須與找社宅原有搜尋規則一致。
2. **B 類租金預設值**：現有搜尋畫面預設 0～40,000 元，訂閱時要儲存此範圍，還是將未調整預算視為不限？需一致。
3. **B 類社宅狀態**：本規劃排除 `housing_status_codes`，因其與招租通知目的高度重疊；若業主要求完全複製搜尋條件須再納入。
4. **生活機能媒合資料來源**：目前只有搜尋紀錄／代碼，沒有明確的社宅生活機能關聯；必須先確認可用 GIS／POI 或其他計算來源。
5. **訂閱時間與既有招租**：本版建議「只通知條件生效後開始的招租」，晚訂閱者不補寄已在招租中的案件；若業主希望訂閱當下即可收到進行中招租，須調整排程規則。
6. **招租案唯一識別**：國住都及六都推送 `rental_schedule.schedule_code` 是否必填且穩定？若可空導致重複建立招租案，必須另訂通知去重方式。
7. **寄送頻率**：每日 08:00 為建議值；若招租期短或需高時效，可調整頻率但不需要修改資料表架構。
