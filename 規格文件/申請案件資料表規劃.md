# 申請案件資料表規劃

v1.1｜2026-11-16｜PostgreSQL｜時間採 `timestamptz`，畫面以 `Asia/Taipei` 顯示。

依據 [db.txt](db.txt) 與[申請案件查詢功能規格](申請案件查詢功能規格.md)的取號、進度回傳 API 規劃。沿用既有表名，案件資料由來源權責機關回傳。

## 一、資料表用途

| 資料表 | 用途 | 一筆資料代表 |
|---|---|---|
| `application_case` | 案件基本資料與目前狀態 | 一個統一案件編號。 |
| `application_case_member` | 案件目前成員，供申請人身分比對及案件查詢 | 某案件目前名單中的一位成員。 |
| `application_case_status_history` | 狀態及成員異動歷程，保存當時完整成員快照 | 一次成功接收且內容有異動的案件進度。 |

一個案件可有多位成員及多筆歷程。取號後尚未回傳進度時，只有案件主檔。首次有效回傳後，成員至少一位、歷程至少一筆。

**本版規劃採「狀態或成員任一異動皆留歷程」。** 每筆歷程保存更新完成後的完整成員名單。狀態與有序成員內容完全相同的重送，沿用既有資料與接收時間。

既有 `application_case_number_counter` 繼續負責機關／年度／縣市的原子配號，欄位沿用 [db.txt](db.txt)。配號與案件新增在同一交易提交。

## 二、案件基本資料表 `application_case`

### 2.1 用途

保存取號時的案件基本資料及最近一次有效回傳的案件狀態。案件列表讀取本表，再關聯社宅、房型與權責機關顯示名稱。

### 2.2 欄位

| 欄位名稱 | 中文名稱 | PostgreSQL 型態 | 必填 | 預設值 | 關聯 | 用途／規則 |
|---|---|---|---|---|---|---|
| id | 案件識別碼 | uuid | 是 | `gen_random_uuid()` | PK | 平台案件主鍵。 |
| case_number | 統一案件編號 | varchar(14) | 是 | 無 | UNIQUE | 統一案件編號，由機關、年度、縣市及流水號組成。 |
| agency_code | 來源權責機關代碼 | varchar(2) | 是 | 無 | 來源機關代碼，由服務驗證 | 須符合呼叫憑證的授權機關，建立後保留。 |
| case_year | 民國案件年度 | varchar(3) | 是 | 無 | — | 三碼民國案件年度，取來源傳入年度。 |
| city_code | 社宅所在地縣市代碼 | varchar(1) | 是 | 無 | 字母縣市對照資料，由服務驗證 | 社宅所在地的一碼大寫字母代碼，與社宅所屬縣市一致。 |
| serial_number | 案件流水號 | integer | 是 | 無 | — | 平台配發的流水號，範圍 1～99999999，組碼時補零至八碼。 |
| applied_at | 申請日期與時間 | timestamptz | 是 | 無 | — | 來源原始申請日期與時間，取號時由 caseData.appliedAt 寫入。 |
| housing_code | 申請社宅代碼 | varchar(50) | 是 | 無 | 來源機關與社宅代碼對照 | 保存來源 caseData.housingCode。 |
| housing_id | 社宅主檔識別碼 | uuid | 是 | 無 | FK → `housing.id` | 取號時依來源機關與社宅代碼解析的社宅主鍵。 |
| room_type_code | 申請房型代碼 | varchar(30) | 是 | 無 | 對應 `housing_class.item_code`，限 ROOM_TYPE | 取來源 caseData.roomTypeCode，由服務驗證為該社宅的房型。 |
| status | 目前案件狀態 | varchar(20) | 否 | NULL | — | 目前案件狀態，限 ACCEPTED、MOVED_IN、MOVED_OUT。取號時為 NULL，首次回傳進度後填入。 |
| progress_received_at | 最新進度接收時間 | timestamptz | 否 | NULL | — | 最近一次狀態或成員實際異動的接收時間，與該次歷程 recorded_at 相同。 |
| created_at | 建立時間 | timestamptz | 是 | `now()` | — | 取號及案件建檔時間。 |
| updated_at | 最後異動時間 | timestamptz | 是 | `now()` | — | 實際異動時由服務更新。相同內容重送時保留原值。 |

### 2.3 狀態與資料規則

| 狀態值 | 顯示名稱 | 寫入時機 |
|---|---|---|
| NULL | 尚未回傳進度 | 取號時建立主檔，成員及歷程皆為零筆。 |
| ACCEPTED | 已受理 | 來源機關回傳此狀態。 |
| MOVED_IN | 已入住 | 來源機關回傳此狀態。 |
| MOVED_OUT | 已退租 | 來源機關回傳此狀態。 |

| 項目 | 規則 |
|---|---|
| 案件編號 | 固定十四碼，例如 CH115A00000842，須等於 agency_code＋case_year＋city_code＋八碼補零流水號。 |
| 建立 | A6.1.1 驗證全部基本資料後配號，原子更新計數器並新增主檔。取號成功仍須等待 A6.1.2 回傳狀態與成員。 |
| 狀態預設 | status 預設 NULL。僅在收到有效進度時寫入來源回傳的狀態。 |
| 異動範圍 | A6.1.2 更新 status、progress_received_at、updated_at 與成員及歷程。案件編號、來源機關、申請時間、社宅及房型沿用取號時資料。 |
| 首次回傳 | 同一交易寫入目前成員及第一筆歷程。主檔狀態須等於最新歷程的 to_status。 |
| 會員列表 | 有狀態及完整成員後，依目前 member_order = 1 的申請人身分比對會員。成員的其他關係不會自動取得查閱權限。 |
| 狀態更正 | 沿用現行 API 的更正規則，接受三種有效狀態間的更正，新增歷程保留異動順序。實際轉換限制由來源業務確認。 |

## 三、案件成員表 `application_case_member`

### 3.1 用途

保存來源機關最近一次有效回傳的完整成員名單，保留傳入順序。第一筆為申請人，其餘為其他案件成員。

### 3.2 欄位

| 欄位名稱 | 中文名稱 | PostgreSQL 型態 | 必填 | 預設值 | 關聯 | 用途／規則 |
|---|---|---|---|---|---|---|
| id | 成員識別碼 | uuid | 是 | `gen_random_uuid()` | PK | 目前成員列的識別碼。 |
| case_id | 案件識別碼 | uuid | 是 | 無 | FK → `application_case.id` | 所屬案件。 |
| member_order | 成員順序 | integer | 是 | 無 | 同案順序唯一 | 對應 members 陣列順序，由 1 連續起算，1 為申請人本人。 |
| national_id_encrypted | 身分證字號密文 | bytea | 是 | 無 | — | 正規化身分證字號經應用程式加密後的密文。 |
| national_id_hash | 身分證字號比對雜湊 | char(64) | 是 | 無 | 同案證號唯一 | 正規化身分證字號的 HMAC-SHA256，供去重及與會員已驗證身分比對。 |
| id_key_version | 證號金鑰版本 | smallint | 是 | 無 | — | 身分證字號加密與 HMAC 使用的金鑰版本，須為正整數。 |
| name | 姓名 | varchar(200) | 是 | 無 | — | 來源姓名，須有實際文字。 |
| birth_date | 出生日期 | date | 是 | 無 | — | 西元生日，須為有效日期且不晚於臺灣當日。 |
| gender | 性別 | varchar(20) | 是 | 無 | — | 來源性別文字，例如「男」「女」。 |
| title | 稱謂 | varchar(50) | 是 | 無 | — | 來源稱謂，例如「本人」「配偶」「子女」。申請人由 member_order = 1 判斷。 |
| created_at | 建立時間 | timestamptz | 是 | `now()` | — | 本份目前成員資料的建立時間。 |

### 3.3 資料規則

- A6.1.2 每次回傳完整 members，至少一位，所有成員的證號、姓名、生日、性別、稱謂均必填。
- 平台保留原始順序，同案證號去重。輸入先正規化並驗證，再與目前的有序業務內容比對。
- 成員內容異動時，在案件交易內以完整名單取代目前名單，並把同一份新名單寫入當次歷程快照。歷程透過快照保存當時內容。
- 只回傳申請人一位代表目前名單改為一位。回傳空陣列視為驗證失敗，全部資料維持原狀。
- 會員比對使用目前申請人的 national_id_hash，並與 member_profile 的 HMAC 正規化方式及有效金鑰版本一致。金鑰換版須維持現行比對可用。

## 四、案件狀態歷程表 `application_case_status_history`

### 4.1 用途

記錄每次平台成功保存的狀態或成員異動，以及該次異動完成後的完整案件成員。查詢舊歷程時解密該筆快照，取得當時名單。

### 4.2 欄位

| 欄位名稱 | 中文名稱 | PostgreSQL 型態 | 必填 | 預設值 | 關聯 | 用途／規則 |
|---|---|---|---|---|---|---|
| id | 歷程識別碼 | uuid | 是 | `gen_random_uuid()` | PK | 歷程識別碼。 |
| case_id | 案件識別碼 | uuid | 是 | 無 | FK → `application_case.id` | 所屬案件，保留各次歷程。 |
| sequence_no | 歷程序號 | integer | 是 | 無 | 同案件內唯一 | 由 1 起算，每次實際異動加 1，在案件鎖內配發。 |
| change_type | 異動類型 | varchar(30) | 是 | 無 | — | INITIAL、STATUS_CHANGED、MEMBERS_CHANGED、STATUS_AND_MEMBERS_CHANGED，由平台比對後填入。 |
| from_status | 異動前案件狀態 | varchar(20) | 否 | NULL | — | 更新前狀態，僅第一筆為 NULL，其餘須等於前一筆 to_status。 |
| to_status | 異動後案件狀態 | varchar(20) | 是 | 無 | — | 本次更新後狀態，限 ACCEPTED、MOVED_IN、MOVED_OUT。僅成員異動時與 from_status 相同。 |
| members_snapshot_encrypted | 完整成員快照密文 | bytea | 是 | 無 | 當次完整成員快照 | 完整有序成員 JSON 經應用程式加密後的密文，至少含申請人。 |
| members_snapshot_key_version | 成員快照金鑰版本 | smallint | 是 | 無 | — | 成員快照加密金鑰版本，須為正整數，供歷史資料解密使用。 |
| recorded_at | 歷程記錄時間 | timestamptz | 是 | 無 | — | 平台在案件鎖內確認異動的時間，與本次 progress_received_at 及 receivedAt 相同。 |
| source_agency_code | 回傳機關代碼 | varchar(2) | 是 | 無 | 來源機關代碼，由服務驗證 | 由呼叫憑證取得，須與案件 agency_code 相同。 |
| request_id | 請求追蹤識別碼 | varchar(100) | 是 | 無 | 介接請求追蹤識別 | 平台產生，供查詢該次介接紀錄。 |

### 4.3 異動類型

| change_type | 使用情境 | 前後狀態 |
|---|---|---|
| INITIAL | 第一次成功回傳進度與成員 | NULL → 本次狀態。 |
| STATUS_CHANGED | 狀態改變，成員內容及順序相同 | 前後不同。 |
| MEMBERS_CHANGED | 狀態相同，成員內容或順序改變 | 前後相同。 |
| STATUS_AND_MEMBERS_CHANGED | 狀態與成員內容或順序皆改變 | 前後不同。 |

只有狀態異動時也保存完整成員快照。成員異動包含增減成員、變更順序及任一業務欄位更正。

### 4.4 成員快照內容

解密後的 JSON 為有序陣列，每項保存下列欄位。

| 欄位名稱 | 中文名稱 | JSON 型態 | 用途／規則 |
|---|---|---|---|
| member_order | 成員順序 | number | 當次名單順序，由 1 起算。 |
| national_id | 身分證字號 | string | 當次正規化身分證字號，隨整份快照加密保存。 |
| name | 姓名 | string | 當次姓名。 |
| birth_date | 出生日期 | string | 當次生日，YYYY-MM-DD。 |
| gender | 性別 | string | 當次性別文字。 |
| title | 稱謂 | string | 當次稱謂。 |

快照由平台以驗證成功的 members 產生。來源 API 沿用既有欄位，歷程與加密欄位由平台自行填入。

### 4.5 資料規則

- 歷程只新增，保留原始紀錄。由資料庫權限或 trigger 限制一般應用程式對既有歷程的修改及刪除。
- 同案用 sequence_no 排序。歷程主鍵及快照均獨立於目前成員列的 ID，成員名單更新後仍能查回舊版本。
- 第一筆序號為 1、from_status 為 NULL、change_type 為 INITIAL。後續每筆 from_status 須等於上一筆 to_status，最新歷程的 to_status 須等於主檔 status。
- 同狀態且有序成員內容相同的重送回傳成功，updated 為 false，保留原進度接收時間及歷程筆數。比對採正規化後業務內容，排除隨機密文及資料列 ID。
- 舊金鑰版本保留受控解密能力，歷史快照的可讀取性隨金鑰生命週期管理。
- recorded_at 記錄平台接收異動的時間。實際入住或退租生效日須由來源另行提供，目前 API 尚無此欄位。

## 五、同一交易的寫入流程

1. 驗證機關憑證、案件歸屬、狀態與完整成員內容。
2. 鎖定 application_case，讀取目前狀態及有序成員。
3. 比對狀態、成員內容及順序。完全相同時回傳成功與原接收時間。
4. 首次或有異動時，取得同案下一個歷程序號及本次時間，依異動範圍產生 change_type。
5. 產生成員完整加密快照，必要時更新目前成員，新增歷程，更新主檔 status、progress_received_at、updated_at。
6. 全部成功後提交，任一步驟失敗全數回滾。

來源依既有 API 約定逐筆按業務順序送出。介面尚無來源 revision 或生效時間，平台按取得案件鎖並成功提交的順序保存。

## 六、限制與索引

| 資料表 | 限制／索引 | 用途 |
|---|---|---|
| application_case | UNIQUE (case_number) | 統一案件編號唯一。 |
| application_case | UNIQUE (agency_code, case_year, city_code, serial_number) | 配號組合唯一。 |
| application_case | CHECK 編碼長度、格式、組碼一致及流水號範圍 | 維持十四碼格式與各欄位一致。 |
| application_case | CHECK status 為 NULL 或三種有效狀態，status 與 progress_received_at 同時為空或同時有值 | 維持取號與進度資料完整性。 |
| application_case | INDEX (agency_code, status, applied_at DESC)、INDEX (housing_id) | 支援案件查詢。 |
| application_case_member | UNIQUE (case_id, member_order)、UNIQUE (case_id, national_id_hash) | 順序與同案證號去重。 |
| application_case_member | CHECK member_order ≥ 1、id_key_version ≥ 1、文字有實際內容 | 基本資料檢核。 |
| application_case_member | INDEX (national_id_hash, member_order, case_id) | 支援本人案件比對。 |
| application_case_status_history | UNIQUE (case_id, sequence_no)、INDEX (request_id) | 支援歷程排序及請求追查。 |
| application_case_status_history | CHECK sequence_no ≥ 1、members_snapshot_key_version ≥ 1、密文非空、狀態及異動類型組合正確 | 檢核歷程必要欄位。 |
| 三表外鍵 | NO ACTION | 保留案件、成員與歷程的關聯。 |

跨表規則由同一案件鎖與交易維持，包含序號連續、成員順序由 1 連續起算、最新狀態一致、來源機關一致及快照內容與當次成員一致。

## 七、資料變化範例

下列為示意資料，A、B、C 代表三位不同人。

| 操作 | 主檔目前狀態 | 目前成員 | 新增歷程 |
|---|---|---|---|
| 取號 | NULL | 空 | 無。 |
| 首次回傳已受理及 A、B | ACCEPTED | A、B | 第 1 筆 INITIAL，NULL → ACCEPTED，快照 A、B。 |
| 同內容重送 | ACCEPTED | A、B | 無，回傳原接收時間。 |
| 狀態相同，成員新增 C | ACCEPTED | A、B、C | 第 2 筆 MEMBERS_CHANGED，ACCEPTED → ACCEPTED，快照 A、B、C。 |
| 改為已入住，成員相同 | MOVED_IN | A、B、C | 第 3 筆 STATUS_CHANGED，ACCEPTED → MOVED_IN，快照 A、B、C。 |
| 改為已退租，成員改為 A、B | MOVED_OUT | A、B | 第 4 筆 STATUS_AND_MEMBERS_CHANGED，MOVED_IN → MOVED_OUT，快照 A、B。 |

查第 1 筆歷程時取得 A、B，查第 3 筆取得 A、B、C，案件目前名單則為 A、B。成員僅存在於歷史快照時，案件權限仍依目前申請人及權責機關驗證。

## 八、畫面資料查詢

### 8.1 畫面與資料來源

| 查詢內容 | 資料來源 | 讀取方式 |
|---|---|---|
| 目前 progress.html 案件列表 | application_case、目前申請人成員、社宅與代碼主檔 | 用目前申請人比對登入會員後，回傳主檔目前狀態及列表欄位。 |
| 目前案件成員 | application_case_member | 完成案件授權檢查後，依 case_id、member_order 取得目前名單。 |
| 歷次狀態與異動類型 | application_case_status_history | 完成案件授權檢查後，依 case_id、sequence_no 查詢歷程摘要。 |
| 某次歷程的成員 | 該筆歷程的 members_snapshot_encrypted | 取得指定歷程後由後端解密，依當次 member_order 呈現。 |

現有 progress.html 的七欄資料如下。成員及歷程供詳細查詢端點使用。

| 畫面欄位 | 來源 |
|---|---|
| 申請社宅 | application_case.housing_id → housing.name，所在地接 county.name、district.name。 |
| 房型 | application_case.room_type_code → housing_class 的 ROOM_TYPE 群組 item_name。 |
| 統一案件編碼 | application_case.case_number。 |
| 申請時間 | application_case.applied_at，以臺灣時間轉為民國日期及 24 小時制時間。 |
| 案件狀態 | application_case.status，轉為「已受理／已入住／已退租」。 |
| 權責機關 | 依 application_case.agency_code 取得申請案件查詢規格第 4.2 節定義的機關名稱。 |
| 前往查看 | 依來源機關取得後端設定的外連網址，由現有外部網站確認視窗開啟。 |

以下 SQL 使用 PostgreSQL 綁定參數。$1 為後端從登入身分取得的 member_profile.id；$2 為選取的案件 UUID；$3 為選取的歷程 UUID。所有查詢均比對目前申請人的證號 HMAC 及金鑰版本。HMAC 的正規化、金鑰及版本須依既有成員與會員比對規則維持一致。

### 8.2 本人案件列表

```sql
SELECT
    c.id AS case_id,
    c.case_number,
    c.applied_at,
    c.status,
    c.agency_code,
    h.name AS housing_name,
    county.name AS county_name,
    district.name AS district_name,
    room.item_name AS room_type_name
FROM application_case AS c
JOIN application_case_member AS applicant
    ON applicant.case_id = c.id
    AND applicant.member_order = 1
JOIN member_profile AS viewer
    ON viewer.id = $1
    AND viewer.is_enabled
    AND viewer.id_no_hash = applicant.national_id_hash
    AND viewer.id_no_key_version = applicant.id_key_version
JOIN housing AS h ON h.id = c.housing_id
JOIN county ON county.id = h.county_id
LEFT JOIN district ON district.id = h.district_id
LEFT JOIN housing_class AS room
    ON room.group_code = 'ROOM_TYPE'
    AND room.item_code = c.room_type_code
WHERE c.status IS NOT NULL
ORDER BY c.applied_at DESC, c.id DESC;
```

同案件的申請人順序唯一，因此每案回傳一列。主檔 status 為 NULL 的只取號案件不列入列表。依現行畫面一次回傳本人案件，標題總筆數取結果列數，零筆時為 0。後端依 agency_code 補上機關名稱與外連網址，再提供給畫面。

### 8.3 目前案件成員

```sql
SELECT
    person.id,
    person.member_order,
    person.name,
    person.birth_date,
    person.gender,
    person.title
FROM application_case_member AS person
JOIN application_case AS c ON c.id = person.case_id
JOIN application_case_member AS applicant
    ON applicant.case_id = c.id
    AND applicant.member_order = 1
JOIN member_profile AS viewer
    ON viewer.id = $1
    AND viewer.is_enabled
    AND viewer.id_no_hash = applicant.national_id_hash
    AND viewer.id_no_key_version = applicant.id_key_version
WHERE c.id = $2
    AND c.status IS NOT NULL
ORDER BY person.member_order;
```

案件權限每次依目前申請人檢查。畫面若需顯示證號，由後端依授權取得 national_id_encrypted、id_key_version 解密並產生所需顯示文字。

### 8.4 案件歷程摘要

```sql
SELECT
    history.id AS history_id,
    history.sequence_no,
    history.change_type,
    history.from_status,
    history.to_status,
    history.recorded_at
FROM application_case_status_history AS history
JOIN application_case AS c ON c.id = history.case_id
JOIN application_case_member AS applicant
    ON applicant.case_id = c.id
    AND applicant.member_order = 1
JOIN member_profile AS viewer
    ON viewer.id = $1
    AND viewer.is_enabled
    AND viewer.id_no_hash = applicant.national_id_hash
    AND viewer.id_no_key_version = applicant.id_key_version
WHERE c.id = $2
    AND c.status IS NOT NULL
ORDER BY history.sequence_no DESC;
```

MEMBERS_CHANGED 的前後狀態相同，畫面以「成員資料異動」顯示；STATUS_AND_MEMBERS_CHANGED 可顯示「狀態及成員異動」。摘要先顯示時間、異動類型與前後狀態，點選其中一筆再取得當時成員。

### 8.5 指定歷程的完整成員

```sql
SELECT
    history.id AS history_id,
    history.sequence_no,
    history.members_snapshot_encrypted,
    history.members_snapshot_key_version
FROM application_case_status_history AS history
JOIN application_case AS c ON c.id = history.case_id
JOIN application_case_member AS applicant
    ON applicant.case_id = c.id
    AND applicant.member_order = 1
JOIN member_profile AS viewer
    ON viewer.id = $1
    AND viewer.is_enabled
    AND viewer.id_no_hash = applicant.national_id_hash
    AND viewer.id_no_key_version = applicant.id_key_version
WHERE c.id = $2
    AND history.id = $3
    AND c.status IS NOT NULL;
```

後端依金鑰版本解密完整快照，還原第 4.4 節的有序陣列，再提供該次成員資料給已授權的畫面。密文與金鑰版本由後端處理。查詢同時限制案件與歷程 ID，確保選取的歷程屬於該案件。

後臺權責機關的案件查詢則以憑證或登入帳號授權的 agency_code 限定案件，沿用相同的目前資料與歷史快照來源。
